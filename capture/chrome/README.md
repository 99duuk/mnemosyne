# 카테고리 기반 수집기

현재 기본 진입점은 `node collector/cli.mjs --help`이다. 전체 카테고리(기본), 포함/제외 목록, 30줄 페이지 순회, SQLite 보관·중단/재개를 지원한다. 실행법과 한계는 [수집 안내](../../docs/COLLECTION.md)를 참고한다. 아래 내용은 기존 확장 프로그램 검증에 대한 기록이다.

## Chrome 확장 프로그램 저장 테스트

브라우저가 글을 열면 Manifest V3 확장 프로그램이 현재 글의 텍스트를 저장하고, 브라우저 자동화가 해당 문서의 저장 완료를 확인한 뒤 다음 글로 이동하는 제한된 실험이다.

**데스크톱 앱과 Chrome for Codex는 사용하지 않는다.** 실행 드라이버는 Playwright와 별도 Chromium 프로필이다. 사용 중인 Chrome 프로필·쿠키·탭은 사용하지 않는다. 개인 Chrome에 확장을 설치하는 작업은 별도다.

## 구성

- `extension/`: 실제 설치 가능한 Chrome 확장 프로그램. 초기 상태는 중지이며 한 세션에서 1~50개 한도로 설정한다.
- `test/core.test.mjs`: 대상 문서·탭·시점 검증과 revision 검사.
- `test/browser.mjs`: 실제 브라우저에서 확장을 로드해 합성 또는 공개 글 두 개를 검증하는 드라이버.

확장은 지정한 탭·블로그에서 세션 한도(1~50개)만 처리하며 30분 후 만료된다. 새로운 세션 시작은 확장 자체의 화면에서만 가능하다. 차단·접근 실패 시 드라이버는 중지한다.

## 실행

이 디렉터리에서:

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
```

기본 브라우저 테스트는 합성 HTML로 응답을 대체하며 네이버 글을 요청하지 않는다. 실제 공개 글 테스트는 명시적인 대상 지정이 필요하다.

```sh
MNEMOSYNE_TEST_BLOG=대상블로그ID node test/browser.mjs --live
```

실환경 모드는 홈의 링크에서 두 개의 게시글 주소만 선택한다. 첫 글 저장 → 첫 글 재방문(중복) → 두 번째 글 저장 순으로 진행한다. 매번 현재 문서 ID·작업 ID·revision을 확인한 뒤 이동한다. 저장 실패 시 전체 반복을 중단한다.

브라우저를 닫고 다시 열어 저장이 유지되는지 확인할 수 있다. 테스트 세션은 종료 시 중지하고 브라우저도 종료한다. 백그라운드 자동 재개는 등록하지 않는다.

## 저장 결과

원문은 확장의 `chrome.storage.local`에 저장된다. 저장 후 다시 읽고 SHA-256을 검증해야 `SAVED`/`DUPLICATE`를 반환한다. 동일 문서의 변경된 텍스트는 새 revision과 이전 revision 연결로 보존한다.

드라이버는 추가로 아래 디렉터리에 JSONL·문서별 Markdown/JSON·검증 결과를 저장한다.

```text
~/Library/Application Support/Mnemosyne/browser-test/live-*/
  report.json
  posts.jsonl
  posts/<document>/<revision>/post.md
  posts/<document>/<revision>/record.json
  profile/
```

실제 원문과 브라우저 프로필은 저장소 밖에 둔다. 디렉터리는 소유자만 접근할 수 있게 만들며, export 파일 권한은 0600이다. Git에 추가하지 않는다.

## 저장 자료 확인

`viewer/index.html`을 일반 브라우저에서 열고 `posts.jsonl`과 필요하면 같은 실행의 `report.json`을 파일 선택창에 넣는다. 제목·게시일·본문 길이·경고를 목록으로 훑고, 글을 클릭해 원문·주소·revision·저장 상태를 확인할 수 있다. 브라우저 안에서 필수 필드와 revision SHA-256도 다시 검사한다. 파일은 업로드되지 않고 로컬 브라우저에서만 읽힌다.

DataGrip으로 보려면 JSONL을 SQLite 테이블로 변환하는 별도 import 작업이 필요하다. 현재 저장 형식은 파일과 JSONL이라 HTML 검수 화면이 원문 대조에는 더 직접적이다. DataGrip용 SQLite export는 스키마를 먼저 고정한 뒤 추가한다.

## 검증 범위와 한계

- SmartEditor ONE의 텍스트 문단만 지원한다. 구형 에디터는 추출 실패로 끝날 수 있다.
- 제목·게시일 원문 표기·본문이 있어야 저장한다. 게시일을 임의의 절대 시각으로 변환하지 않는다.
- 본문이 잠시 안정되었는지 검사하지만, 이것만으로 지연 로딩의 완전성을 증명하지 않는다.
- 저장된 텍스트와 렌더링된 지원 문단의 일치를 비교한다. 이미지·표·영상 등은 저장하지 않고 경고로 남긴다.
- 공개된 모든 글이나 목록의 완전성은 검증하지 않는다.
- 자료 상태는 `UNREVIEWED`, `rag_eligible: false`다. 기술 테스트 승인과 저작권·플랫폼 이용 허락을 동일시하지 않는다.
- 추출 결과와 페이지 안의 완료 배지는 웹페이지에서 보이는 정보다. 드라이버는 이를 성공의 유일한 근거로 쓰지 않고 확장 저장소의 영수증과 실제 기록을 확인한다.
- 이 저장 형식은 테스트용이며 기존 Python capture store로 자동 병합하지 않는다.

## 수동 설치 시

Chrome의 확장 프로그램 관리 화면에서 개발자 모드를 켜고 `extension/` 폴더를 압축해제된 확장으로 로드한다. 대상 게시글을 연 다음 확장 팝업에서 블로그 ID를 입력하고 시작한다. 이후 지정한 탭에서 글을 열면 자동 저장한다. 테스트는 두 문서로 제한되며 팝업에서 중지·JSONL 내보내기를 할 수 있다.

개인 Chrome 설치는 이번 자동 브라우저 테스트와 구분한다. 현재 CLI 수집기는 별도 Chromium이 글을 열고 확장의 저장을 확인한 뒤 SQLite로 옮긴다.
