# 브라우저 이동 + Chrome 확장 저장 테스트

검증일: 2026-09-16 KST

## 결과

실제 공개 글 두 개를 로그인 없이 열고, 실제 Manifest V3 확장 프로그램으로 텍스트를 저장하는 실험을 통과했다. 사용자가 요청한 역할 분담 중 **확장 프로그램의 추출·저장과 저장 완료 확인 후 다음 글 이동**을 검증했다.

**데스크톱 앱과 Chrome for Codex는 사용하지 않는다.** 페이지 이동은 Playwright가 별도 Chromium 프로필에서 수행했다. 이 테스트는 일반 Chrome에 설치할 수 있는 확장의 추출·저장 동작과 로컬 자동화 드라이버를 검증한다.

| 검사 | 결과 |
|---|---|
| 첫 공개 글 | `SAVED`, 텍스트 1,993자 |
| 첫 글 재방문 | `DUPLICATE`, 추가 revision 없음 |
| 두 번째 공개 글 | `SAVED`, 텍스트 2,845자 |
| 원문 비교 | 두 글 모두 렌더링된 지원 문단과 저장 텍스트 일치 |
| 저장 완료 확인 | 문서 ID·작업 ID·revision·저장소 재읽기·SHA-256 확인 |
| 브라우저 종료 후 재시작 | 두 기록이 그대로 유지됨 |
| 종료 상태 | 자동 저장 세션 중지, 테스트 브라우저 종료 |

‘원문 일치’는 텍스트 추출 대상 문단에 한정한다. 이미지·표·영상의 보존이나 전체 블로그의 완전성을 증명하지 않는다. 홈에서 발견한 두 링크를 테스트했으며, 대표성이나 RAG 품질을 평가한 표본은 아니다.

2026-09-16 재검증에서 같은 공개 글 두 개를 다시 처리했다. 결과는 `SAVED`(1,993자, 4.3초) → `DUPLICATE`(1,993자, 4.0초) → `SAVED`(2,845자, 5.2초)였고, 저장 파일·revision 해시·재시작 보존 검사를 다시 통과했다.

접근 감시 결과는 네이버 문서 탐색·본문 요청 10건 모두 HTTP 200, `blocking_signal: null`이었다. 감시 범위 안에서 401/403/429, 보이는 CAPTCHA 입력·프레임, 선택된 접근 제한 안내는 관찰되지 않았다. 이는 이번 소량·단일 실행에서 차단이 발생하지 않았다는 뜻이며, 네이버가 향후 대량 접근을 허용한다는 보장은 아니다.

## 별도 합성 검증

- 단위 테스트 4개 통과: URL 정체성, 다른 탭·화자·프레임·만료 차단, 불완전 payload 차단, revision 해시.
- 실제 확장을 로드한 합성 브라우저 테스트 통과: 직접 본문과 iframe 본문, 중복 처리, 수정 revision 연결, 세 번째 문서 제한, 다른 작성자 제외, 재시작 보존.
- 초기 실환경 실패 원인: 페이지 배치용 상위 table을 본문 내부 table로 오인해 모든 문단을 제외했다. 판정을 본문 내부로 한정하고, 합성 fixture에 외부 배치 table과 내부 콘텐츠 table을 함께 넣어 회귀 검증했다.
- 기존 Safari/Chrome Service 경로는 이번 변경 및 검증 대상이 아니다.

## 최신 50개 실행

2026-09-16에 RSS의 최신 항목 50개를 주소 발견용으로 사용하고, 각 게시글 페이지를 순차 방문해 저장했다. RSS 설명문을 본문 자료로 저장하지 않았으며, 각 실제 게시글 페이지의 본문을 확장 프로그램이 추출했다.

- `rss_items: 50`, 고유 문서 `50`, 저장된 records `50`
- 총 저장 본문 약 57,501자
- 50개 모두 `SAVED`, 각 저장 후 revision 해시와 렌더링 본문 일치 확인
- 접근 감시: 문서 응답은 모두 HTTP 200, `blocking_signal: null`
- CAPTCHA·401/403/429·선택된 접근 제한 안내 관찰 없음
- 결과: `~/Library/Application Support/Mnemosyne/browser-test/live50-3XjsG8/`
- 모든 원문·JSONL은 저장소 밖에 있고, `posts.jsonl`은 0600, 상위 디렉터리는 0700이다.

이는 RSS가 제공한 당시 최신 50개를 처리한 실행 결과다. 블로그 전체의 완전성, 향후 반복 실행의 무차단, 플랫폼·저작권 이용 허락을 의미하지 않는다. 차단 신호가 나타나면 중단하도록 했고 우회·재시도·CAPTCHA 해결은 하지 않았다.

## 남은 것

1. 데스크톱 앱 없이 사용할 운영 흐름을 정한다. 기본안은 사용자가 다음 글을 열고 확장이 자동 저장하는 방식이며, 별도 로컬 컨트롤러가 링크 이동까지 맡길 때는 범위·중단 조건을 먼저 고정한다.
2. 구형 에디터·지연 로딩·게시글 형식별 추출 범위를 확인한다.
3. 전체 수집은 이번 두 문서 테스트와 별도 범위다. 목록의 완전성, 처리량, 중단·재개와 사용 범위를 먼저 결정한다.
