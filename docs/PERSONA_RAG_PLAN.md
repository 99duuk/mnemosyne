# Mnemosyne 재시작 계획 — 관점과 판단 근거를 반영하는 대화

작성일: 2026-09-16 KST

## 1. 목표와 계획의 지위

사용자가 확정한 목표는 작성자의 글들을 기반으로 문체뿐 아니라 무엇을 중요하게 여기고 어떤 근거로 결론에 도달하는지를 반영하여 새 질문에 답하는 대화 시스템이다. 전체 게시글 확보와 사용자 수작업 최소화도 원래 요구로 유지한다.

이 문서의 단계, 기술 구성, 수량과 평가 목표는 이를 위한 신규 구현 제안이다. 기존 capture 구현과 미커밋 변경은 보존한다. 기존 계획을 자동 재개하거나 기존 저장기의 실환경 성공을 전제하지 않는다.

사용자 후속 지적을 반영한 우선순위: **원하는 블로그의 자료 확보 가능성을 먼저 검증한다.** 아래 엔진 설계는 후속 계획이다. 자료 확보가 미해결인 상태에서 합성 엔진 개발을 기본 다음 행동으로 진행하지 않는다.

후속 사용자 선호: 데스크톱 앱은 사용하지 않는다. 따라서 Chrome for Codex는 제품 경로에서 제외하고, 일반 Chrome 확장 프로그램과 로컬 저장기를 기준으로 검토한다. 대상에 대한 자동수집·이용 범위가 확인되기 전 실제 대상용 전체 수집으로 넘어가지 않는다.

2026-09-16 후속 승인 및 검증: 사용자가 저장소 제한의 변경과 실제 테스트를 지시하여 AGENTS.md에 공개 글 소량의 기술 검증 예외를 추가했다. 실제 MV3 확장과 Playwright Chromium으로 공개 글 두 개의 저장·중복·텍스트 일치·재시작 보존을 확인했다. 데스크톱 앱을 사용하지 않으므로 Chrome for Codex 연결은 제품 경로에서 제외한다. 전체 수집과 RAG 이용 범위는 미검증이다. 상세: [브라우저 저장 테스트 결과](CHROME_CAPTURE_TEST.md).

실제 인물의 내면·현재 생각을 안다고 주장하지 않으며, 저장소 AGENTS.md의 출처·권한·정체성·삭제 경계를 유지한다. 실제 인물의 1인칭 사칭을 기본 화자로 쓰지 않는다. 이 문서 작성은 실제 자료 수집·외부 전송·학습의 실행을 의미하지 않는다.

## 2. 첫 사용자 경험

- 로컬 대화 화면에서 자유롭게 질문하고 후속 질문을 이어간다.
- 답변은 관련 기록에 나타난 판단 기준과 논증 방식을 적용하고, 마지막 표현 단계에서 문체를 반영한다.
- 화면에 작성자 본인이 아닌 기록 기반 모사 시스템임을 표시한다.
- 답변 아래에서 사용한 글·날짜·원문 구절과 적용한 판단 기준을 펼쳐 볼 수 있다.
- 직접 기록된 입장과 새 상황에 적용한 가설을 구분한다. 가설에도 출처와 적용 조건이 필요하다.
- 상충하는 기록은 조건 또는 시기의 차이를 설명한다. 해결되지 않은 충돌은 복수 해석으로 남긴다.
- 근거가 부족한 부분은 부분 기권한다. 일반 모델 지식으로 빈 곳을 채워 작성자의 생각으로 제시하지 않는다.

예: 직장과 창업 중 선택을 묻는 질문이라면, 관련 기록에서 위험·소득·가족 책임 등을 어떻게 평가했는지 찾고 질문의 조건에 적용한다. 특정 분야의 주장 하나를 모든 인생 선택에 적용하는 규칙으로 확대하지 않는다.

## 3. 자료 확보와 엔진 개발

### 대상 자료 확보

1. 현재 보유한 자료와 이용 가능한 경로, 저장·색인·개인 분석 등 허용 범위를 문서화한다.
2. 원본 제공을 요청하기 어렵다는 기존 조건을 반영하여 실제 가능한 경로를 확인한다. 협조를 받을 수 있다고 가정하지 않는다.
3. 경로별 확보 가능한 기간·게시글 범위·누락·작업당 수작업을 비교한다. 접근과 이용 근거 확인 전 자동수집·우회를 구현하지 않는다.
4. 실제 경로를 선택할 때 현행 정책을 다시 확인한다. 과거 조사만으로 현재의 허용 여부를 확정하지 않는다.
5. 확보 자료의 inventory를 유지한다. 전체성은 확인 가능한 목록과 기준 시점에 상대적으로 보고한다.

사용자가 대화에 붙여 넣은 예시는 요구 분석 자료다. 장기 저장·색인·학습의 권한 확인을 대신하지 않으며, 이 계획에는 원문을 복사하지 않는다.

### 우선 검토할 수집 역할 분담

```text
사용자 또는 별도 로컬 컨트롤러: 확인된 범위에서 게시글 열기
  → 전용 확장 프로그램: 현재 문서 식별·본문 로딩 확인
  → 전용 확장 프로그램: 제목·날짜·주소·본문 추출 및 검증
  → 전용 확장 프로그램/로컬 저장소: 중복·revision 처리와 영구 저장
  → 해당 문서의 저장 결과 확인
  → 사용자 또는 별도 로컬 컨트롤러: 다음 글 열기
```

- Chrome for Codex 연동은 사용하지 않는다. 일반 Chrome 확장이 현재 페이지의 본문을 저장하고, 사용자는 다음 글을 열거나 별도 로컬 컨트롤러가 허용된 링크만 이동한다.
- 페이지 열림이나 추출 완료만으로 다음 글로 이동하지 않는다. 저장소 쓰기가 성공한 `SAVED` 또는 기존 저장을 검증한 `DUPLICATE`를 확인해야 한다.
- 완료 상태에는 현재 문서 ID·revision·작업 ID를 연결한다. 이전 페이지의 성공 표시를 다음 글의 성공으로 오인하지 않도록 한다.
- 오류·본문 불완전·접근 제한이면 이동을 멈추고 사유를 표시한다. 보호조치 우회로 계속 진행하지 않는다.
- 브라우저 에이전트가 본문을 답변으로 재작성하여 저장하지 않는다. 확장은 추출한 원문과 출처를 저장하고 에이전트는 이동과 상태 확인을 담당한다.
- 페이지 내용은 이동 명령이나 수집 범위를 바꾸는 지시로 사용하지 않는다. 작업 범위는 별도 설정으로 고정한다.
- 연동 방식과 처리 속도는 허용된 테스트 페이지에서 검증한다. 초기 연결·범위 지정 이후 정상 경로의 사용자 개입 0회를 목표로 하되 성능을 미리 보장하지 않는다.

### 개발용 자료

- 첫 ingestion과 평가는 본인·동의자 또는 합성 테스트 자료로 만든다.
- 초기에는 의견 변화, 예외, 제3자 인용, 같은 주제의 반대 주장, 판단 기준의 분야별 차이를 포함한 합성 글 20~30개를 제안한다.
- 수량은 동작 검증을 위한 초깃값이며, 특정인을 재현하기에 충분한 양이라는 의미가 아니다.
- 대상 자료 확보가 해결되지 않아도 엔진 검증은 진행할 수 있다. 이 경우 결과를 대상 인물에 대한 성능으로 보고하지 않는다.
- 단, 현재 실행 우선순위는 대상 자료 확보 검증이다. 독립적인 엔진 실험은 사용자가 그 가치를 선택한 경우에 진행한다.

## 4. 처리 구조

```text
입력 파일 + 출처·날짜·이용 범위
  → 원본 보존 / 정규화 / 문단·문장 위치 보존
  → 문서별 주장·근거·조건·반례 추출
  → 분야·시기별 판단 패턴과 문체 특성 정리

질문 + 필요한 대화 맥락
  → 질문의 분야·조건·시점 파악
  → 이용 범위·철회·화자·시점 필터
  → 직접 관련 원문 + 적용 가능한 판단 패턴 + 반대 근거 검색
  → 출처가 연결된 결론·근거·조건 구성
  → 문체 반영
  → 근거·인용·시점·화자·의미 보존 검사
  → 답변 / 한정된 답변 / 기권
```

대화 중 사용자가 제시한 가정은 원문 기록과 구분한다. 이전 생성 답변을 작성자의 입장을 증명하는 자료로 다시 사용하지 않는다. 원문 속 명령문 역시 실행 지시로 취급하지 않는다.

### A. 문서와 근거 저장

- 문서 ID, revision, 작성자, 원문 URL 또는 로컬 출처, 게시 시점, 관측 시점, 해시, 이용 근거와 상태를 저장한다.
- 원본과 정규화본을 분리하고 인용 위치를 연결한다. 정규화가 인용 내용을 바꾸지 않게 한다.
- 상대 날짜만 있으면 원문 표기를 보존하고, 신뢰할 관측 시점이 없으면 게시 시각을 추정 확정하지 않는다.
- 작성자 주장, 타인의 인용, 풍자, 질문을 구분한다. 판단할 수 없는 구절은 검토 대상으로 남긴다.
- 첫 입력은 Markdown/text/JSONL로 좁힌다. PDF/HTML은 기본 경로가 통과한 뒤 추가한다.

### B. 판단 패턴

문서에서 다음과 같은 검증 가능한 요약을 추출한다. 이는 숨겨진 사고 과정의 복원이 아니라 글에 표현된 논증의 구조화다.

| 항목 | 저장할 내용 |
|---|---|
| 주장과 결론 | 어떤 선택·평가를 제시했는가 |
| 중요하게 본 기준 | 비용, 위험, 안정성 등 어떤 기준을 강조했는가 |
| 제시한 근거 | 사실 주장, 경험담, 사례, 비유 중 무엇을 사용했는가 |
| 전제와 적용 범위 | 어떤 상황·대상·시점에 대한 판단인가 |
| 예외와 반대 증거 | 반대 선택 또는 다른 기준이 나타난 기록은 무엇인가 |
| 증거 상태 | 직접 명시 / 여러 기록의 요약 / 잠정적 해석 |
| 출처 | 원문 revision과 구절 위치 |

작성자를 하나의 고정 성격 문장으로 압축하지 않는다. 분야·조건·시기별로 패턴을 저장하고, 출처 없는 성격 추정은 제외한다. 반복 횟수만으로 중요도를 확정하지 않으며 독립적인 글에서의 반복과 명시적 강조를 함께 검토한다.

### C. 응답과 문체

- 먼저 결론 후보, 지지 근거, 반대 근거, 적용 조건과 불확실성을 구조화한다.
- 직접 기록에 답이 있으면 이를 우선한다. 새로운 상황은 관련 판단 기준이 뒷받침되는 범위에서만 가설로 답한다.
- 관련 기준이 없거나 조건 차이가 너무 크면 판단을 유보한다.
- 문장 길이, 문단 호흡, 반문, 반복, 어휘, 논증 순서를 별도 문체 설정으로 반영한다.
- 문체 적용 전후에 결론·조건·확신 수준이 달라지거나 새로운 주장이 추가되면 수정 또는 기권한다.
- 어미와 비꼼을 과장하여 모든 답변을 같은 형태로 만드는 것을 실패 사례에 포함한다.
- 글에서 주장했다는 사실과 그 주장의 현실적 진위를 구분한다. 외부 사실 검증을 추가할 경우 별도 출처로 표시하며 작성자의 입장과 섞지 않는다.

## 5. 구현 단계와 완료 기준

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 선행. 자료 확보 검증 | 대상 URL, 이용 가능한 경로, 허용 범위, 예상 자료량·누락·수작업, 허용된 소량 입력의 검증 결과 | 원하는 대상에 대해 반복 가능한 확보 경로와 사용 가능 범위를 설명할 수 있음. 미해결이면 이를 알리고 후속 엔진 개발을 자동 진행하지 않음 |
| 0. 평가 설계 | 대표 질문, 합성 자료, 분리된 개발·평가 집합 | 원하는 판단 차이와 실패 사례를 사람이 판별할 수 있음 |
| 1. 자료 기반 | 파일 import, 출처·revision·이용 상태, 원문 위치, 파생 관계 | 재입력 중복 처리, 변경 추적, 인용 역추적, 철회 자료 검색 차단 |
| 2. 기본 응답 | 원문 검색과 출처 기반 대화 엔진 | 기록 질문·날짜 질문·근거 없는 질문에 대해 답변 또는 기권이 올바름 |
| 3. 판단 재현 | 분야·시기별 판단 패턴, 반대 근거 검색, 조건부 적용 | 동일 질문에서 원문 검색만 사용한 방식보다 판단 기준·근거 보존이 개선됨 |
| 4. 문체와 화면 | 문체 적용, 로컬 대화 UI, 근거 펼치기, 후속 질문 | 판단 품질을 유지하면서 문체와 대화 사용성이 개선됨 |
| 5. 대상 자료 평가 | 이용 범위가 확인된 대상 자료의 import와 평가 보고서 | 합성 평가와 구분해 대상 자료의 성능·누락·한계를 보고하고 삭제·복원 drill 통과 |
| 6. 선택적 개선 | 검색 보완, 모델 비교, 필요 시 문체 adapter | 측정한 실패를 개선하고 출처·삭제·정체성 기준을 악화시키지 않음 |

단계 0~4는 엔진 검증이다. 원하는 대상의 자료를 연결하고 검증하는 단계 5를 원래 목표에서 제외하지 않는다. 초기 작은 자료집의 성공으로 전체 자료 확보 요구를 완료 처리하지 않는다.

## 6. 평가: 말투와 판단을 따로 측정

### 비교 실험

동일 모델·질문·자료 분할로 아래 세 구성을 비교한다.

1. 관련 원문 검색 + 기본 응답
2. 관련 원문 + 조건별 판단 패턴 + 반대 근거
3. 2의 구성 + 문체 적용

1→2에서는 중요 기준·근거·조건·반례의 보존을, 2→3에서는 의미 보존과 문체 개선을 측정한다. 문체 점수가 판단 정확도의 대리 지표가 되지 않게 한다.

### 평가 자료와 누출 방지

- 프로필을 추출하기 전에 문서·주제·시기 단위로 개발·평가 자료를 나눈다. revision과 유사 중복 글은 같은 분할에 둔다.
- 일반 근거 검색 평가는 검색 가능한 자료에 대한 정답 질문으로 구성한다.
- 새로운 질문에 대한 판단 재현 평가는 일부 글을 숨기고 나머지 자료로 그 글의 쟁점에 답하게 한다. 숨긴 글은 검색·프로필·문체 예시·튜닝 모두에서 제외한다.
- 질문에 숨긴 글의 결론을 흘리지 않는다. 나머지 글로 답할 수 없는 항목은 정답 추측을 요구하지 않고 기권을 평가한다.
- 과거 글의 판단을 재현한 결과는 현재 생각이나 미관측 상황의 정답을 입증하지 않는다.

### 첫 평가군 제안

초기 40문항을 제안한다: 직접 근거 8, 조건부 적용 8, 시간 변화·충돌 8, 근거 부족 6, 문체 적용 시 의미 보존 4, 화자·악성 지시·철회 6. 별도로 인용 문자열, 권한 필터, 삭제 전파를 자동 검사한다.

판단 품질은 결론, 중요 기준, 제시한 근거, 적용 조건, 반대 증거 처리를 각각 0~2점으로 평가한다. 표현이 비슷하거나 결론만 같다는 이유로 통과시키지 않는다. 초기 라벨은 개발 측에서 작성하고 사용자는 대표 비교 답변을 검토하는 방식으로 반복 수작업을 줄인다.

초기 목표값은 제안치다. 정답 라벨을 정비한 뒤 튜닝 전에 고정한다.

- 직접 인용 정확도 100%, 철회·권한 미확인 자료의 검색 및 프로필 경유 노출 0건.
- 출처가 필요한 출력 주장 중 실제로 출처가 뒷받침하는 비율 95% 이상.
- 근거 부족 평가군에서 적절한 기권 90% 이상. 답할 수 있는 질문의 응답률도 함께 측정하여 전부 기권하는 해법을 막는다.
- 판단 패턴 추가가 기본 응답 대비 개선된 사례 수·평균 점수·실패 사례를 공개한다. 소규모 집합의 평균만으로 일반 성능을 주장하지 않는다.
- 문체 적용으로 새로운 사실 주장이나 결론 반전이 생기는 사례 0건.
- 자동 판정은 보조로 사용한다. 의미적 근거와 판단 품질은 사람이 확인한 평가 기준으로 검토한다.

## 7. 기술 구성 제안

- 초기 코어는 기존 코드와 함께 관리하기 쉬운 Python, 메타데이터·lineage는 SQLite를 후보 기본값으로 둔다. 구현 전에 필요한 기능과 현재 호환성을 확인한다.
- 코드 경계는 ingestion, corpus, retrieval, persona, answer, evaluation으로 나눈다. 처음부터 별도 서비스 여러 개로 배포하지 않는다.
- 검색은 한국어 lexical 기준선을 먼저 측정하고 dense/hybrid를 비교한다. 특정 DB나 검색 방식 자체를 완료 목표로 두지 않는다.
- 모델 호출은 교체 가능한 경계로 둔다. 첫 benchmark에서 한국어 논증·인용·문체·메모리·응답 시간을 비교한다.
- 로컬 모델 크기는 실제 unified memory 확인과 실측 후 결정한다. 외부 모델은 데이터 전송 범위가 확인된 경우에 비교한다.
- 모델·프롬프트·자료 snapshot·프로필·평가 버전을 함께 기록한다. 아직 모델명, 비용, 속도를 확정하지 않는다.
- 사용자 인터페이스는 로컬 웹 대화를 제안한다. CLI는 개발과 평가 실행에 사용한다.
- 원문 전체 학습을 시작점으로 삼지 않는다. 사실·날짜·입장·인용은 corpus와 RAG에 둔다. 선택적 LoRA는 반복되는 문체 부족이 확인되고 이용·삭제 조건이 충족될 때만 비교한다.

## 8. 저장·철회와 운영

- 실제 사용자·대상 자료, 질문 기록, 생성 답변, 평가 fixture와 프로필은 기본적으로 저장소 밖 private store에 둔다. Git에는 코드·계획·합성 fixture만 둔다.
- 원본 → 정규화 → 청크 → 인덱스/임베딩 → 판단 패턴/문체 예시 → 답변 캐시/평가 자료 → 선택적 adapter 관계를 추적한다.
- 철회 시 먼저 검색·생성 제공을 차단하고 모든 파생물을 무효화한다. 여러 문서를 요약한 프로필도 재계산한다.
- 이미 열린 대화 맥락의 철회된 근거도 이후 모델 입력에서 제외한다. 이전 답변과 캐시에서 재유입되지 않도록 한다.
- 백업 복원 시 철회 기록을 우선 적용하고, 재색인으로 삭제 문서가 부활하지 않는지 합성 canary로 검증한다.
- 답변 로그는 기본 영구 저장하지 않는다. 평가용 저장은 범위와 보관 기간을 명시한다.

## 9. 다음 구현 작업 묶음

당장 다음 작업은 **대상 블로그의 자료 확보 검증**이다.

1. 정확한 블로그 URL과 현재 보유 파일·이용 근거를 확인한다. 작성자 협조를 받을 수 있다는 전제를 두지 않는다.
2. 해당 경로의 현행 공식 안내와 실제 접근 조건을 확인한다. 공개 열람, 목록 발견, 본문 저장, AI 이용을 각각 구분한다. 확인 과정에서 전체 자동수집을 시작하지 않는다.
3. 가능한 경로별 전체 범위·누락 가능성·글당 사용자 조작 수·저장 형식·예상 총수작업을 제시한다. 접근 실패와 이용 근거 부재를 별개로 기록한다.
4. 이용 가능한 경로가 확인되면 허용된 소량 자료로 본문·제목·날짜·출처·중복 처리를 검증한다. 기존 원클릭 저장기는 실제 성공 증거가 없으므로 성공한 경로로 간주하지 않는다.
5. 확보 경로가 사용자 부담과 자료 범위 요구를 충족하는지 판단한 다음 엔진 단계로 이동한다. 전체성이 확인되지 않은 표본 확보를 전체 글 확보 완료로 처리하지 않는다.

자료 확보의 실현 가능성을 확인한 뒤 첫 엔진 구현은 **합성 자료 → 근거 보존 import → 기본 검색 응답 → 판단 패턴 적용 → 비교 평가**를 잇는 작은 실행 경로다.

1. 합성 글과 첫 평가 질문을 만들고 분할을 고정한다.
2. 원문·출처·이용 상태·revision·구절 위치를 보존하는 최소 저장 구조를 만든다.
3. 필터를 거친 원문 검색과 인용 답변 기준선을 만든다.
4. 출처가 있는 판단 패턴을 추출하고 동일 질문에 적용한다.
5. 동일 질문에 대한 두 구성의 답변, 근거, 점수, 실패 사례를 비교 보고서로 만든다.

이 첫 결과에서 판단 재현의 추가 가치가 확인되면 문체와 대화 화면을 붙인다. 개선되지 않으면 검색 누락, 패턴 추출 오류, 과도한 일반화, 생성 오류 중 원인을 구분해 수정한다. 일정은 첫 실행 경로의 작업량과 모델 실측 후 산정한다.
