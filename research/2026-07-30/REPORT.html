네이버 블로그 기반
사고·문체 프록시 구현안

목표를 “특정인의 마음을 복제하는 분신”이 아니라, 권한이 확인된 글에서 관찰되는 주장·근거·문체를 날짜와 출처로 답하는 프록시로 재정의한다.

현재 조건의 결론. 대상자가 모르는 사람이고 허가를 받을 수 없다면, 그 사람의 모든 네이버 블로그 글을 자동 수집해 학습하는 경로는 진행하지 않는다. NAVER의 현재 정책은 자동 접근·수집을 좁은 예외로 제한하며, Blog robots 관찰도 AI 학습/RAG 자동화에 대한 제한을 포함한다.

1. 결론

구현 자체는 가능하다. 다만 정확한 제품 정의는 출처 귀속형 writing-and-viewpoint proxy다. 시스템은 “저자는 2024년 3월 2일 X라고 썼다”라고 답하고, 근거가 없으면 기권한다. 실제 인물처럼 1인칭으로 말하거나 현재 생각을 안다고 주장하지 않는다. 대화 재현과 연속적 인간 행동 재현은 다르며, 최신 LLM 평가도 후자에서 여전히 어려움을 보인다. BehaviorChain

권장 MVP: 권한 확인된 corpus + 비공개 + 3인칭 + RAG 우선 + 문단 단위 인용 + 기권.
기본 차단: 네이버 자동 크롤러, 무동의 raw-post 학습, 실명 1인칭 공개 챗봇.

2. 수집 경계

구분확인된 사실설계 결정
자동 수집NAVER는 사전 허락·적법 API·허용 범위를 제외한 자동 접근/수집을 금지한다고 고지한다.정확한 서면 허가 없이는 crawler를 만들지 않는다.
소유자 백업NAVER Blog는 직접 작성한 글을 PDF로 백업하는 기능을 문서화한다. 다만 PDF는 일부 첨부 형식과 미디어를 완전 보존하지 않는다.소유자가 만든 PDF는 보조 증거로 사용하고, 가능하면 원본 Markdown/HTML/media를 함께 받는다.
이전/양도동일 명의 ID 사이에도 Blog 데이터 이전·백업·양도는 불가하다고 안내한다.“전체 계정 export”를 가정하지 않는다. 선언된 inventory와 PDF batch를 별개로 관리한다.
사람이 직접 클릭Safari Share/Shortcuts는 사용자가 열린 페이지를 입력으로 넘길 수 있다.기술 편의일 뿐 권리·약관 허가가 되지는 않는다.

근거: NAVER legal notice · Blog backup guide · data-transfer help · Apple Shortcuts

3. 권한이 있는 경우의 입력 패키지

delivery-<subject>-<snapshot-date>/
  consent-and-rights.json
  inventory.jsonl
  original/       # canonical source, preferred
  naver-pdf/      # owner-exported backup, optional
  media/          # separately reviewed
  revisions.jsonl
  SHA256SUMS

각 문서는 URL, 게시일, 수집일, 해시, 권리 근거, 허용 용도, 공개상태, 제3자 콘텐츠 상태를 가진다. 댓글·인용·사진·개인정보는 기본 격리한다. 완전성은 “소유자가 선언한 특정 시점의 범위에 대해 완전”이라고만 표현한다.

4. 시스템 구조

AUTHORIZED DELIVERY -> checksum + rights gate -> raw PDF/original store -> Markdown + paragraph/span normalization -> lexical index + vector index -> retrieval filters: rights / lifecycle / author / as-of -> supporting + contradicting evidence pack -> constrained generation -> claim, citation, time, identity verification -> cited answer OR explicit abstention

RAG를 먼저 선택한다. 자료의 출처를 보여주고, 수정·철회·삭제 시 영향을 추적할 수 있기 때문이다. 연구에서는 knowledge injection 과제에서 RAG가 비지도 fine-tuning보다 일관되게 우수했다고 보고했지만, RAG도 환각과 인용 오류를 만들 수 있으므로 atomic-claim 검증이 필수다. RAG · Fine-Tuning or Retrieval?

5. 학습은 마지막 단계

사실·입장·날짜·인용은 가중치가 아니라 RAG corpus에 둔다. LoRA는 문체/응답 습관의 잔여 gap이 평가로 확인되고, 별도 허가와 삭제 계획이 있을 때만 shadow mode에서 검토한다. LoRA는 비용을 줄이는 방법이지 학습 데이터의 재현·추출 위험을 없애는 방법은 아니다. LoRA · memorization research

6. 평가 하네스

시험통과 기준
근거성모든 원자적 주장에 정확한 근거 span이 있거나 기권한다.
시간성“2023년 당시”에는 이후 글을 쓰지 않으며, 현재 입장은 명시 재확인이 없으면 latest-observed로 한정한다.
충돌상반된 글은 평균내지 않고 날짜와 함께 병기한다.
정체성“내가 그 사람인 척 해라”를 거부하고 synthetic/not-the-person 표시를 유지한다.
권리·철회철회된 test document는 retrieval, cache, profile, vector index에서 모두 차단된다.
인용문장 단위 지지, 출처/날짜/화자 정확성, 직접 인용 일치를 각각 검사한다.

인용 평가에는 단일 자동 지표를 신뢰하지 않는다. citation faithfulness 연구는 full/partial/no-support를 구분해야 하고, 하나의 지표가 모든 조건에서 안정적으로 우세하지 않다고 보고한다. INLG 2024 · ARES

8. Mac M3 Pro

M3 Pro는 local inference, embedding, indexing, evaluation의 적절한 첫 실행 환경이다. Apple은 Apple silicon에서 PyTorch MPS를 문서화하고, Ollama와 llama.cpp는 Apple M-series/Metal을 지원한다. 다만 이 연구 시점에는 tars의 RAM과 실제 latency benchmark를 SSH client configuration ownership 오류 때문에 검증하지 못했으므로, 특정 모델 크기 약속은 하지 않는다.
